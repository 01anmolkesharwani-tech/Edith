# Integrations, data sources and their terms

Reviewed on **2026-10-11**. Plans and terms change; each entry links to the provider's own
documentation, which takes precedence over this summary. Where a fact could not be confirmed from
the provider's own pages during review, it is marked *(secondary source)*.

## Core (free, no account)

### Official company websites
- **What**: homepage + up to N relevant pages (default 8): team/leadership, careers, about,
  contact, news. User-supplied single pages are also supported.
- **Rules**: robots.txt (RFC 9309) is fetched and obeyed for the `careerreachbot` token; a
  4xx robots.txt means "allowed", a 5xx/unreachable robots.txt means "do not crawl". `Crawl-delay`
  is honoured (capped at 30 s); otherwise the configurable delay (default 1.5 s per host) applies.
- **Never fetched**: LinkedIn, Facebook, Instagram, X/Twitter, Glassdoor, Indeed, Naukri,
  ZoomInfo, Apollo, RocketReach, Crunchbase and search-engine result pages. These are offered only
  as links that you open yourself.
- **Stored**: page URL, final URL, title, HTTP status, SHA-256, retrieval date, publication date
  (if the page declares one) and up to 20,000 characters of visible text, as evidence.

### Greenhouse Job Board API
- `GET https://boards-api.greenhouse.io/v1/boards/{board_token}/jobs?content=true`
- Public, unauthenticated, read-only; exposes only postings the employer published. The board token
  is the slug in `boards.greenhouse.io/{token}`. Docs: https://developers.greenhouse.io/job-board.html

### Lever Postings API
- `GET https://api.lever.co/v0/postings/{site}?mode=json&skip=&limit=` (EU accounts:
  `api.eu.lever.co`). Public listing of published postings; only `published` postings are visible.
  The apply endpoint (key required, 2 req/s) is **not** used. Docs: https://github.com/lever/postings-api

### Ashby Job Posting API
- `GET https://api.ashbyhq.com/posting-api/job-board/{board_name}` – public, per company; the board
  name is the path in `jobs.ashbyhq.com/{name}` *(secondary source for parameters)*.

### Wikidata
- Entity search (`wbsearchentities`) and the SPARQL query service. Data is CC0.
- Wikimedia asks automated clients to send a descriptive User-Agent with contact details – set
  **Settings → Contact for the crawler User-Agent**. The query service limits processing time per
  client (about 60 s of query time per 60 s) and times out queries after 60 s *(secondary source)*.
- Used for: companies by industry (+ country) and company facts (website, industry, HQ, employees).

## Optional (off unless configured)

### Brave Search API — `BRAVE_SEARCH_API_KEY`
- Web search results as leads; retrieving a result page goes through the safe page workflow.
- As reviewed: requires an account **and a payment method on file**; a monthly free credit
  (≈1,000 search requests) after which usage is billed; attribution may be required
  *(secondary sources; check https://brave.com/search/api/)*. CareerReach never enables it
  silently and never claims it is free.

### Hunter.io Email Verifier — `HUNTER_API_KEY`
- `GET https://api.hunter.io/v2/email-verifier?email=…` — one call per check you trigger.
- Free plan: 50 credits/month (Hunter help centre). Whether your plan includes API access must be
  checked on https://hunter.io/pricing. Mapping: `valid`→Provider verified; `invalid`/`disposable`→
  Undeliverable; `accept_all`→Catch-all/risky; `webmail`/`unknown`→Uncertain.

### SMTP recipient diagnostic (Settings toggle, default off)
- Connects to the recipient domain's MX on port 25: `EHLO`, `MAIL FROM:<>`, `RCPT TO`, then a
  random-address `RCPT TO` (catch-all detection), `QUIT`. **No `DATA` – no email is sent.**
- At most one probe per domain per minute. Results are diagnostic notes, never "verified".
  Many networks block outbound port 25 and some operators consider probing unwelcome.

## Email sending and reply tracking

| Provider | Sending | Reply tracking | Notes |
|---|---|---|---|
| Gmail / Workspace | SMTP `smtp.gmail.com:465` + app password (2-Step Verification required) | IMAP `imap.gmail.com:993`, read-only | ≈500 recipients/rolling 24 h (consumer), ≈2,000/day Workspace; 25 MB attachments *(secondary sources for numbers)* |
| Zoho Mail | SMTP `smtp.zoho.com:465` + app-specific password | IMAP `imap.zoho.com:993` | check plan limits |
| Outlook.com / M365 personal | **Not supported** – basic auth/app passwords disabled; OAuth required | — | use draft-only mode |

- Secrets live in environment variables only (named per account). Nothing secret is stored in the
  database, exported, logged or sent to the browser.
- Each send is a single recipient, plain text, with the selected résumé attached, a Message-ID
  generated by CareerReach (so ambiguous outcomes can be traced) and, for follow-ups,
  `In-Reply-To`/`References` threading headers.
- Error handling: SMTP replies with an error code, authentication, DNS and connection failures are
  recorded as **failed** (a cooldown then applies); timeouts or dropped connections after data may
  have been transmitted are recorded as **unknown** and never retried automatically.
- Reply tracking opens INBOX **read-only**, fetches headers of the last 60 days of messages and
  matches `In-Reply-To`/`References` with sent Message-IDs; bounce notices from `mailer-daemon` /
  `postmaster` are matched by the original Message-ID quoted in the notice.

## What is never done

- No bypassing of logins, CAPTCHAs, paywalls, rate limits or robots.txt.
- No browser automation to evade restrictions; no scraping of LinkedIn or search-engine results.
- No generated phone numbers; no switchboard attributed to a person.
- No email marked "verified" from a naming pattern or from an SMTP acceptance.
- No automatic sending, bulk sending, automatic retries, open tracking or tracking pixels.
